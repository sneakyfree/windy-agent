- **When Eternitas refuses the agent's token because it is retired, suspended or revoked, the agent stops.** The same happens when this computer's key was revoked. There is no model call of any kind (Windy Mind, a provider or the local backup brain), no tool and nothing sent. A person who writes gets one plain line ("<Name> is retired, so it isn't answering. You can restore it until <date>. ..."); another agent gets nothing. The stop survives a restart, and only the next good mint lifts it. While the agent runs, it checks with Eternitas once a minute, so a retire or a restore takes effect within 75 seconds even when nobody writes. It used to fall through to "Mind unavailable" and could wake the local backup brain.

A passport-token agent finds its passport from the stored token when `ETERNITAS_PASSPORT` is unset. A refused forced refresh and a revoked key's mint back off (doubling from 60 s to 1 h) instead of repeating every minute, while a retired or suspended stop keeps the 60 s check. Only a 200 that carries a usable token (or Eternitas' explicit "kept") lifts the stop. After a move that didn't finish, `windy home pair` sets aside a key that Eternitas shows as revoked (renamed, never deleted) so a new one can pair.
