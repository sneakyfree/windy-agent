- Old key backups no longer live for ever. A `credentials.json.bak-*` older than 30 days is overwritten with zeros (+ fsync) and removed, but only when every key in it is in the current file or listed as retired or revoked on the passport's live key list. Any other status, or a key the list doesn't show, keeps the backup. If the list can't be read, nothing that needs it is deleted. The newest backup is always kept, and an unreadable one is kept. The env-file copies (`.bak-ept-`, `.bak-deregister-`) are now written 0600 whatever the env file's mode; existing ones are set to 0600, and those older than 30 days are overwritten and removed, keeping the newest of each kind. The zero overwrite is best effort (copy-on-write filesystems and SSDs may keep old blocks); it is not a secure erase. Runs inside `ensure_registered`; logs carry counts only, never a kid.
