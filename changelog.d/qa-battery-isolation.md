- **A lab test run can never act as a real agent or spend a person's keys.** On 11-01 the weekly QA battery on Windy 0 ran AS Zero (Grant's real agent). It had sourced the lab agent's env but not its state folder, so windyfly found Zero's registered key and used it, plus Grant's own provider keys (29 calls). New `python -m windyfly.lab_guard [--mint]` refuses (exit 2, names only, never a value) unless the run is a test passport (ET26-TEST-*) with its own token and its own registered key outside the real agent's folder. No person's provider key or Claude login may be readable, and a dry-run mint must come back as that test passport. The battery script now runs entirely in the lab agent's home (HOME, state folder, env file, key file) behind the guard. It is the Windy 0 version (lab agent, local brief, no Telegram to Grant), now in the repo. The stress harnesses no longer default to Zero's env file or to a `.env` found by walking up.
