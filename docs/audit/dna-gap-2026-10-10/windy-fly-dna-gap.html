What matters most

The foundation is solid: the schema, memory, agent loop, Matrix bot, cost ledger, decay, offline lifeboat and API surface are built and tested. The real problems are a short list of things that look built but do not work, a few that tell the owner something false, and two whole phases (Mission Control, half of Provider Management) that only exist on one side of a wire.

Red: fix or formally retire

  1. Commands that say they worked when they did not. /mode answers "Mode switched to" and stores nothing; the loop never passes a mode to the prompt (C10.9, Gene 0.4). /preset answers "applied" while the default raw_mode=1 makes buddy and engineer produce a byte-identical prompt (C2.7). shape_shift_restore says "restored" from an empty stack. These break principle 9 (say only what's true) in front of the owner. Verified by me in code.
  2. Our own 10-10 tool trim (#490) silently unregistered shape-shift. The tools.sub_agents boot step also carried shape_shift / shape_shift_restore; the commit names only delegate_to_specialist. The shape_shift_bias slider and the autonomy text still point at the removed sub-agent path (C6.3, C6.4). Verified: no caller of register_sub_agent_tool remains.
  3. Intents never infer and never decay. The intent detector's LLM prompt crashes on .format() with KeyError '"has_intent"', the error is swallowed, so no inferred intents are ever made and the Intent Inbox is always empty (C3.11). decay_intents has no caller (C3.12). Crash verified by me.
  4. Memory conflicts overwrite before the owner is asked. upsert_node logs the conflict, then writes the new value anyway; "keep old" cannot restore it; nothing asks the owner in chat (C4.7). A data-integrity gap against principle 8 (never forget).
  5. Personality drift detection never fires. The 24-hour job snapshots before it compares, so the baseline always equals the current value; it also blames the owner's own slider changes on "agent evolution", and nothing shows the alert (C5.3).
  6. Provider settings from the dashboard never reach the agent. The gateway writes <repo>/data/providers.json; the brain reads ~/.windy/providers.json since #338. Dashboard keys, custom providers and the active-model switch are dead ends (C7.3, C7.6, C7.7). The full key is also copied into a file that is not 0600.
  7. Mission Control has no remote end. The gateway dials :3100 on each machine, but no daemon in any repo listens there. All five C8 codons fail; exec and provider sync would send commands and plaintext keys over ws:// (C8.1–C8.5).

Yellow: real but contained

  1. The skill sandbox is not a sandbox. Same uid, full filesystem and network, regex safety gate bypassable and run after execution; JS skills inherit the parent environment; promote never requires the gates. Exposure today is limited: chat only saves and reads text playbooks, and executable skills arrive only over the same-uid local socket (C3.4, C3.5).
  2. Matrix end-to-end encryption is not actually on. No [e2e]/olm in the install, so ENCRYPTION_ENABLED is false, encrypted rooms cannot be read, and the "E2E enabled" log line is false. (Owner DMs are unencrypted today, as phone-tools.v1 states.)
  3. Emotion trend misses sustained stress because assistant turns count as neutral in the 3-in-a-row window; the test passes only because it saves user turns alone (C3.14 is retired anyway).
  4. Event log emits 3 of the 9 specified event types; memory.write, cost.log, conflict.detect and others are never written (C5.7).
  5. Windy Pro tools register unconditionally with a localhost default and human-JWT auth; on passport agents they likely fail, against the 10-10 "register only when configured" rule (C1.10).
  6. Golden tests and regressions run on nothing: no code writes golden tests, most promoted skills are text playbooks, there is no pass/fail history and no alert (C5.5, C5.6).
  7. Phase 7 gateway features have zero tests (discovery, multi-key, OpenRouter OAuth PKCE without a state parameter, validation).
  8. Small truths in the docs: sqlite-vec is a dependency the README says powers memory, but it is never loaded; four different default models across toml, config, .env.example and the loop; the strand says 59 codons, its own checklist lists 67.

Decisions the strand needs (Boss / Grant)

  • Mission Control (Phase 8): build the remote daemon, or retire the phase formally and remove the gateway routes. Principle 4 (dumb tools) and the security exposure both point to retire.
  • Shape-shift (Phase 6): re-register and fix restore, or retire it with the sub-agents it depended on. The slider should not stay in the panel either way unless it does something.
  • Presets under raw mode: either make /preset say plainly that tone sliders are off while raw mode is on, or stop offering presets until raw mode is off.
  • Gateway vs brain state: one providers file (principle 6, one of each).
  • Refresh the strand itself: mark the retired codons (sub-agents, permanent pruning, offline replay, warmth slider, stress prompt), and add genes for what the agent is now built around and the strand never mentions: Windy Mind, Eternitas passports, teams and pair rooms, Mail, Calendar, phone tools, Cloud backups.

Top 5 gaps

  1. Mode switching does nothing. /mode says it switched but stores nothing (commands/core.py:1563-1570), the loop never passes mode to the prompt (loop.py:823), and the bridge's agent_mode value is never read. Focused and neutral modes can't be reached.
  2. sqlite-vec is listed but never used. It is a dependency and the README says it powers memory, but it is never loaded. Semantic recall is plain Python cosine math over stored blobs, and only with the opt-in [semantic] extra, which is off by default.
  3. No overall prompt size cap, and the config knobs for it do nothing. agent.max_context_tokens, max_response_tokens, temperature and memory.max_episodes_per_context are never read; sliders decide those values instead. There are also four different default models across toml, config.py, .env.example and the loop.
  4. The first message is lost to the welcome. On first contact the canned welcome returns early (loop.py:785-794), so the user's first message never reaches the LLM and facts in it (e.g. "My name is …") never become memory nodes.
  5. Two "atomic" spec items aren't atomic, and three behaviours lack tests. MEDIUM write batches commit item by item rather than in one transaction (write_queue.py:161-168). SQL-string migrations aren't atomic because executescript commits implicitly (database.py:818). There are no tests for in-session recall, a CLI chat turn, or the full HIGH > MEDIUM > LOW order.

Scratch scripts are in [a temporary scratchpad, since deleted] (p0check.py, p0cli.py).
